# 完整计时任务的只读检查

本工具独立于正在运行的冻结采集程序，不改变采集源码、规范或种子分配。
在仓库根目录执行：

```powershell
python experiments/v03r/review_20260927/inspect_runtime.py
```

默认只检查冻结源码身份和分片文件元数据，不打开学习曲线。串行写入器打开
下一个分片，说明前一个写入循环已经结束，因此完成量采用“可见分片数减一”
这个保守下界。最后一个分片无论大小如何都不会被当成已完成。该下界不是
内容完整性核验，也不证明进程仍在运行；进程存活应另查 PID 和创建时间。
分片时间间隔给出的剩余时间仅供安排等待，不能替代正式运行时上界。

只有原程序生成 `runtime.json` 和 `baseline.json` 后，才执行：

```powershell
python experiments/v03r/review_20260927/inspect_runtime.py --verify
```

这会绑定冻结提交、源码清单、六项门禁结果、门禁产物摘要、工程键和完整采集
规模，并逐一验证所有分片的内容摘要、记录轴和 incidence 结构。完整读取会
花时间，但不计算效果量、不运行设计选择器。缺少结束产物时返回退出码 2，
不会提前读取尚在写入的分片。成功报告 `MEASURED_AND_VERIFIED` 以及实际
验证的开发形状运行数；元数据进度下界仍保留原始观测语义。

可追加 `--output 新文件路径` 保存快照；拒绝覆盖已有文件。无该选项时只向
终端输出。工具自身测试命令：

```powershell
python -m pytest -q experiments/v03r/review_20260927/test_runtime_inspector.py
```

这些测试覆盖监测逻辑和错误证据拒绝，不等于完整计时完成。`--verify` 通过
也只验证工程计时证据，不使 F0 有效，不授权正式实验。实际效应阈值依据和
协议审查仍需独立完成。正在增长的日志和分片应留在本地，完成核验后再按
仓库既有归档规则发布，不应直接加入本轮提交。
