# V0.5：反馈经验与学习效率

制定稿 v168 · 2026-11-07 · **方案已制定，代码接线与新实验尚未开始**。

依据人类最新要求“可以，你继续制定V0.5吧”，采用本轮已经讨论清楚的广义反馈定义，以及有奖有罚、仅奖励、纯反馈三组比较。本文件是局部研究方案，不是实验结果、科学PASS或自动安排任务。

## 1. 这一阶段只回答什么

> 怎样利用当前与历史反馈，让有限练习更有效、减少无效试错？显式奖励与处罚在其中还有多少额外作用？

强化反馈学习的工作定义：围绕任务目标，利用当前与历史的环境反馈，通过经验学习、必要的解释归因和主动试验，持续改进知识、策略、执行和调查方式，使后续行为更有效或更省资源。

- 反馈包括实际状态变化、任务结果、过程记录、人的/工具的建议，以及过去反馈形成的经验；奖励和处罚是其中的可选数值通道，不是反馈的全部。
- 归因是一个组件，不是整个研究对象。历史复用、主动获得有效经验、选择性修正带来的整体收益都算收益；分组件对照用于解释来源，不用于把这些收益排除出去。
- 普通强化学习也利用反馈。我们的候选改进是更有针对性地组织、补充和利用反馈，而不是宣称“只有本方法使用反馈”。
- 失败可以调查、试验或keep，不强制处罚/改写；成功仍正常学习和保存经验，不触发额外成功归因。试验可以参与形成解释，不要求先彻底想清楚再行动。
- 本轮仍只接真实任务结果通道。人类/Codex文本反馈属于概念范围，但不为此同时增加文本解析、可信度模型或LLM训练。

## 2. 三个研究问题与已有依据

|问题|需要观察的结果|不预设的答案|
|反馈组织是否有用|同交互成本下效果更好，或同效果下少练/少试；早期失败和累计损失减少也算|不要求归因单独超过所有其他组件|
|处罚是否提供额外帮助|相同反馈机制下比较有负奖励与无负奖励的学习曲线|不把旧Alpha的小差异当成普遍无效|
|不提供显式奖惩能否学习|目标与事实反馈保留，纯反馈路径实际持续改进行为|不把没有奖惩误写成没有目标，也不保证它一定更好|

V0.3已观察到前期领先而后追平；V0.4已观察到同效果少试验、同试验数更好结果，也有普通补充练习完整复现反馈方案收益、局部节省但总成本增加的反例。它们决定本轮比较内容，不作为本轮新数据或待重跑案例。

“任务太简单造成平台效应”是待检验解释，不是既定原因。难度提高也可能让调查更贵、更易误判。完成本阶段不要求陌生任务迁移、所有难度都获胜或最终表现永久领先。

## 3. 最小比较矩阵：三种信号 × 两种反馈利用方式

### 奖惩通道

|通道|成功|失败|非终止步骤|共同保留|
|RP：奖励＋处罚|+1|-1|0|目标、事实轨迹、终止类别、历史经验|
|R：奖励、无处罚|+1|0|0|同上；失败不会被隐藏|
|F：纯反馈|不提供标量|不提供标量|不提供标量|同上；仍然学习和选择行动|

无处罚组没有负步奖、超时附加扣分或诊断惩罚。资源成本由研究端记录，不暗塞进学习奖励。失败奖励为0仍可能纠正过高的Q预期；这不等于额外外部处罚。

### 利用方式

|方式|普通学习与历史|额外工作|修正能力|
|P：简单反馈/补充练习|全部真实经验正常学习，保留相同原始历史|失败后按固定规则补充练习；涉及修正时按固定顺序试验可用候选，不做定向查询选择|与S相同的合法局部操作、一次提交和预算|
|S：结构化反馈|同一基础学习器与原始历史，增加条件化经验索引|按当前证据和历史选择可区分猜想的试验；已有适用证据可复用，未知允许有限试验|与P相同；不能靠更大写权限制造优势|

共六组：P-RP、S-RP、P-R、S-R、P-F、S-F。P不是冻结的NoWrite，也不是完全没有反馈；它是简单利用反馈的对照。各通道内S对P检验反馈组织的整体作用；RP对R检验负奖励作用。

F组的决策更新路径与Q学习不同，因此F对RP/R首先是完整方案比较，不能把全部差异都说成单一奖励数字的因果效应。不增加一个故意拿不到学习信号的“零奖励Q学习器”作为稻草人。

## 4. 纯反馈怎样真正学习，以及复用边界

首版使用轻量表格与条件规则，不另起大型学习主体/世界模型研发：

1. 三组共享相同的名义动作语义、可见拓扑和任务目标；从空的本实验经历开始，保存实际状态—命令—执行—后果记录。
2. 共用事实记忆更新：观测到的成功通路、受阻转移、命令/执行偏差都按实际条件记录；不是“一次失败就全局禁用动作”。
3. RP/R在相同初始零值Q表上运行相同TD更新（alpha=1/2，gamma=1），只改变失败奖励。F不消费任务reward/return/TD特征，利用已知可行转移和目标搜索行动；未知转移允许有预算的尝试。F也不将成功/失败另行偷偷变成+1/-1强化信号。
4. 任务目标、终止标签、可行性判断、计数以及学习损失不等于显式奖励通道。F的含义是无外加标量奖惩，不是无偏好、无方向或禁止数值计算。
5. 所有组有相同动作/局部修正菜单、相同可见信息和总交互上限；保留普通学习，记录实际而非只记录上限。探索沿用epsilon=1/10意图，首轮使用共同的事前有限工程坐标，不称正式随机Xi/独立seed研究。

**不能直接照搬v166启动器。** 它读取健康Q*、奖励训练过的checkpoint与两类价值树，执行门控还使用TD变化。V0.5首轮不把这些数值先验或标签带入任何一组；只复用不含答案的语义、实际观察/一次消费/原子提交经验和只读历史设计依据。

这不是排除历史反馈：每个新agent从冷启动到后半程一直保留自身全部经验，S可以学会复用。只是为了比较奖惩通道，首轮不预装来自其他奖励条件的经验。后续再研究现成历史的复用时，单独报获取与摊销成本。

## 5. 首轮任务：只增加一个难度轴

采用独立、版本化的小型“串联岔路房间”环境；旧V0.3/V0.4内核和捕获记录完全不改。每个房间有两个候选出口，局部受阻与实际执行结果只能从任务反馈获知，最终目标公开。命令与实际执行均可观察；控制器局部映射允许所有组按同一规则保留或修正。

新环境是为了显式分离事实后果与奖惩通道、控制决策深度；不是把原内核的每步-0.02偷偷保留在“无处罚”组，也不继承原B1/F1资格。

- 难度轴仅为必须连续处理的决策点数：**1、3、5**；动作集合、反馈字段、奖惩幅度、每回合12步上限不变。
- 每层两份镜像实例，共6份工程案例；局部控制偏差数量保持相同，不同时改变噪声率、奖励密度、观测质量。布局/偏差清单在首个真实调用前固定，不根据效果换世界。
- 每份案例运行六个互不共享学习状态的组，共36条流。各组同初始知识、同任务顺序与外生工程坐标；learner看不到难度标签、真因、故障清单或标准答案。
- 每条流48个主任务：前24冷启动、后24持续练习/回访，**中间不重置状态**。后半程不是新的独立样本，也不是陌生机制迁移。
- 每条流最多12次额外试验，双方单次主任务失败后都最多两次。P按固定规则补充普通回合/循环试验合法局部候选，真实经验立即学习；S可以keep或定向试验。不能通过只允许P一次、却允许S多次来制造优势。
- keep、当前实际可见位置的局部修正、当前证据支持的联合修正构成双方共同候选语法；具体顺序与适用条件在实现manifest里固定，不读取隐藏真因筛候选。受保护状态/未读位置不被顺手改写。
- 不能把镜像布局和48回合称为独立科学seed；这是有限工程比较，不新开400/200确认研究。

具体图坐标、初始映射、P固定循环、S的条件匹配与未知分流规则由下一实现件写清并在运行前固定。本方案不是伪装成已可执行的完整runtime contract；实现若改变主要比较问题或信息边界，必须明确版本变化，不能看到结果后倒填方案。

## 6. 怎么判断更好或更快

不用跨奖励条件的原始回报直接排名。主比较使用所有组共同的外部任务结果和成本：

- **早期改善：**前12、前24及全部48主任务的成功数、失败数和累计失败曲线；同时保留完整逐回合结果，不只挑最终值。
- **达到相同表现的成本：**第一次完成连续12个主任务成功的窗口结束点，以及截至该点全部主任务＋试验回合、环境步数和计算时间。未达到就记NOT_REACHED/右删失，不填0；达到后再失败照实保留，不把该窗口叫永久掌握。
- **同资源效果：**按真实累计交互/环境步数画成功交付曲线；共同资源范围内比较，不因试验上限同为12就声称实际成本相等。
- **代价与稳定性：**重复错误、错误修正、保护性映射误删、回访回退；试验失败不能从总账删除。
- **冷/温阶段：**分别报告前24和后24，另报全过程。历史学习工作只计一次但不能消失；保存与复用开销计入计算时间。首轮不靠删除历史成本宣称总成本更低。

不新增复杂总效用权重。某组效果更好但更费算力，就报告权衡；零/负结果和全部未达到目标都能构成阶段结论。

## 7. 资源与实施顺序

首轮矩阵上限：36 × (48主任务＋12试验) = **2160真实回合**，最多25920环境步。先做一个三通道最小接线，最多另用6个真实回合/72步；完整上限2166回合/25992步。设置本地CPU、总运行20分钟、捕获128MiB的工程保护上限；不使用GPU、付费资源、新科学keys、正式collector或自动安排。没有逐整数大评估bank。

只保留两个实施件，不再拆出长资格链：

1. **新入口最小纵向接线。**真实事件记录→三通道→普通更新→失败试验→一次经验消费/局部提交。重点检查F没有奖励/旧Q*泄入，三组目标和事实可见性一致，成功不额外诊断，双方确实拥有同一候选能力。完成后进入矩阵，不无限添加状态演示。
2. **一次有限矩阵及结果解释。**同组时序串行，保留首次失败/partial与全部结果；修正具体错误用明确新版本，不覆盖捕获或自动反复跑到好结果。检查器只核对必要事件、状态、预算和汇总，不重跑旧fixture或把整个历史仓库重新审计。

时间/空间上限触发时保存完整已发生部分并说明具体瓶颈，不当作研究方向失败。精确源码/场景manifest与执行目录独占在新运行前建立；这不是再次请求已经给过的概念批准。

## 8. 什么算V0.5完成

- 三种信号路径真实接通，F有实质学习机制而非停学；P/S基本能力和成本可比较。
- 首轮矩阵得到可核对的实际结果，或得到明确、可复现的实现/资源阻断；后者标为阻断/未完成，不冒称实验完成。
- 对反馈组织、显式处罚、纯反馈可行性分别给出条件性结论，分清早期优势、同效果节省、最终平台及成本权衡。
- 正、零、负结果都接受；**没有正收益不是继续加实验追赢的理由**。不要求全部指标胜出、全难度胜出、通用RFL、世界模型或陌生任务泛化。

V0.3/V0.4仍按已交付的局部阶段完成；旧正式确认计划保持原状态，不把它们重新挂到V0.5前面。机器可读范围和预算见[plan_v168.json](plan_v168.json)。本次只制定方案，未实施上述学习器、未开始新实验。
