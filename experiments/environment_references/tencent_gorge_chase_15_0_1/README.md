## 3. 迁移时最重要的四个区别

### 3.1 公平能力不能只看组名

官方入门 PPO 只有基础40维特征，其中地图仅取4×4局部块，Actor仅输出八个移动动作。它不是环境能力的上限。

如果反馈组用完整21×21观测、历史与闪现，而纯RL沿用这个裁剪基线，差距就混入了信息和动作权限。下一版四组应使用共同的任务可见输入、合法动作与历史访问/记忆预算；RL可用历史窗口或循环网络，不能故意做成无记忆的弱对照。实际编码、规划及记忆开销分别计数，不假称所有计算天然相等。

### 3.2 事实应记录条件，而不是形成永久禁忌

可研究的反馈不是“这条路曾输过，所以永远禁用”，而是：在怪物相对位置、通道形状、技能冷却、当前速度和资源条件下，采取动作后发生了什么。一次被捕可以触发调查，但不是该路线必然错误的证明；一次幸存也不是普遍安全的证明。

这是本研究对环境的利用方向，不是已经证明的算法效果。不能把怪物的完整真实策略或未观察到的全图预装成反馈模型。

### 3.3 到达上限、被捕和运行异常必须分开

数据协议将存活到步数上限记为任务完成，被捕记为任务失败。环境接口的 `truncated` 同时可能涉及正常上限或异常，平台任务列表中的“已完成”也不等同于英雄获胜。结果需结合有效的任务状态、步数和错误信息解释；`result_code=0` 不能独自充当获胜标签。

因此应报告被捕率、存活时间、宝箱数和分数，不能把旧岔路实验的 SUCCESS/TIMEOUT 标签直接搬来。

### 3.4 纯反馈组不能从数字通道偷偷获得训练奖励

三种反馈方法继续属于完整方案比较：纯反馈、反馈＋奖惩、反馈＋仅奖励；另保留纯RL基线。纯反馈仍有明确任务目标，并可记忆位置、拾取、存活、被捕等事实，不是没有目标的随机行动。

适配时要避免将 `total_score`、`step_score`、`treasure_score` 或评估分数转成纯反馈组的隐藏TD奖励。纯反馈的事实规划/目标排序须公开；事实与目标可以驱动行动，但不能因此宣称它与RL仅差一个数字。处罚的较干净比较是共同反馈机制下的“有处罚”与“仅奖励”。

## 4. 下一步的最小有效方向（建议，尚非冻结协议）

1. 从串联岔路改成同类二维追逐任务，保留局部视野、环路/死路、宝箱、加速和技能时机；不是只增加地图面积。
2. 先以明确的地图/出生条件检验基本历史利用，再增加第二怪物和速度变化。难度在运行前规定，不能看谁赢再挑地图。
3. 四组维持共同观测、动作与外部任务目标。分别看前期累计表现、同环境步数表现、达到共同表现所需交互，以及后续经验复用；不要求最后永远领先。
4. 保留多个独立训练seed，冻结策略后另做足量评估；同一策略的多次评估不是新增独立训练样本。训练图与未参与开发的测试图分开报告。
5. 环境步数、更新次数、事实规划/历史检索、时间成本分开计；追逐任务中活得久会消耗更多步数，不能把早死的低成本直接叫高效率。

## 5. 尚不能从这些文档推出的事情

- 怪物精确寻路、等价路线的tie-break、英雄与怪物的逐步更新顺序，以及交叉路径捕获等全部边界，尚未从本轮阅读的章节得到完整算法定义。
- 数据表列出位置字段，但视野外绝对坐标如何实际屏蔽仍须核对真实返回样本；不能把 `extra_info.frame_state` 的全局帧状态随手混进局部观察输入。
- 登录并能读文档，不等于已获得可本地运行的官方环境、SDK和十张地图的原始数据。若自行实现寻路或地图，只能称为“受该环境启发的本地版本”，不能冒称官方逐步复现。
- 难度增加不保证反馈组优势增大；它使目前尚未检验的历史、条件依赖与长程后果更有机会被公平检验，正、零、负结果均有意义。
