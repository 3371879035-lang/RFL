# V198：12 小时五组训练，历史提案必须再经实际验证

按用户最新要求，把尚未启动的长任务改为 **最多 12 小时**，不恢复聊天自动任务，不要求助手持续轮询。程序自行保留检查点、核对核心环节计数、执行资源上限并生成终点报告。V197 已执行的短接线检查原样保留，不改源、不重跑。

## 五组和公平对照

1. **RL-plain**：真正普通 RL。奖励/处罚、正常 TD、真实经验回放；不接定向试验、候选择优、教师和蒸馏。
2. **RL-outer**：与普通 RL 每个种子的起始模型完全相同，但接候选试训、历史调度、实际验证和 SLEEP。
3. **F0**：无环境奖励包、无 Q；实际事实测量与公开目标偏好，接反馈闭环。
4. **F-RP**：反馈＋奖励＋处罚。
5. **F-R**：反馈＋只有奖励。

4 个既有训练种子，20 条独立延续轨迹。每个共同预算块各组各用 131072 个实际环境步和 1024 次优化器更新。增强组的试验、开发测试、被拒候选和学生更新全部占预算；普通 RL 用相应预算做普通练习/回放。报告评估另列，不能冒充免费学习。匹配环境调用和更新次数，不伪称相同 FLOPs。

## 两种历史各做什么

- **经历/改法历史**：每条记录来自实际经历或实际干预。遇到新的问题节点，按当时可见的局势检索过去真实改法，提出一个值得重新试的动作，而不是照搬旧答案。零效果、不利效果同样保留。
- **学习试验历史（DreamRSI 式调度）**：记录父模型、候选学习操作、实际开发测试结果及成本，调整下一轮先试哪种学习强度。未知分支不编造成已验证结果。

二者都在利用反馈，但对象不同：前者帮助提出“局势里可以怎样改”，后者帮助提出“下一次该怎样试验和学习”。游戏网络没有被说成会自行写自然语言解释或代码。

## 改不改、怎样改的闭环

真实失败 → 查询实际历史 → 候选动作 → 三次真实未来配对试验 → 临时教师学习 → 教师实际任务测试 → 学生真实采集＋SLEEP → 学生分块复查 → 决定采用。

- 历史只给待检验建议；不会因为“以前似乎有效”就直接覆盖参数。
- 教师开发探针 64 回合；学生采用另用 64 回合，分两个独立 32 回合块要求同向，并保留被抓次数条件。
- 学生与普通参考共享实际采集数据、更新次数和小批次随机序列。
- 无合格失败时不强制诊断；无合格教师时不强制 SLEEP；不符合采用条件时继续普通学习。程序记录明确原因，不能用强制更新制造“机制一直在工作”的假象。
- 普通新经历进入各自真实回放和检索；局后诊断数据另存并用于候选学习。

## 运行与交付

本地 CPU、8 个独立任务进程，最多 12 小时，预留最终报告时间；以五组全部完成的最后共同预算块为终点。最终每组每种子 512 回合，地图分层、报告不回流采用；既有地图不是全新研究世界。4 个已有种子不冒充数千独立模型。

任务进程申请临时“系统保持唤醒”，不强制屏幕常亮、不改全局电源配置，退出后解除。实际供电、系统重启等外部中断仍可能导致部分结果，程序不伪称完成、不自动重试。
