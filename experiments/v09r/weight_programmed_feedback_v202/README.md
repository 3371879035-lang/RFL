# V202 权重空间编程：后继关联与实际试验

本轮已经实现、构造新检查点，并完成一次有限实验。不是仅有方案。

**旧 V200 不改；新版本在实验前直接编写初始化权重，实验期间全部冻结。没有梯度训练、游戏适配、SLEEP 或旧实验矩阵重跑。**

## 实际改了什么

1. **保留真实后继关系**：记录 `(当前条件, 动作, 实际后继, 终止标记, 结果, 已知标记)`。不再只依赖条件/动作相似度；通过实际后继关联，把后来的结果用于前面行动的候选价值计算。没有把终局标签硬复制到所有先前动作。
2. **分开噪声与证据不足**：传递事实的一阶矩和联合二阶矩。大量互相矛盾的观测仍保留后果波动，不会因为检索支持度高就被叫作确定结论。
3. **候选和采用分开**：先冻结候选，再让候选与现行策略分别执行新的真实试验；只用实际结果差决定是否采用。试验期间两份策略不吸收新数据；评估回合从不进入记忆或门的判断。
4. **统一数值尺度处理**：根据已观察坐标范围归一化。它不是语义编码器，也不能自动知道哪些特征重要。

## 实测结果

以下是最后 4 个周期的独立评估回合成功率，每格汇总 8 条种子序列、128 个评估回合。每条完整序列有 16 周期、64 个评估回合；对所有机制，探索/试验/评估预算及任务初始条件均相同。评估不进入模型历史。

|新任务|V200 原版|V202 完整版|V202 去实际结果采纳门|V202 去后继关联|
|---|---:|---:|---:|---:|
|延迟选择：2 或 5 步后才有结果|57.81%|97.66%|100.00%|43.75%|
|三步选择共同决定结果|30.47%|92.19%|100.00%|21.09%|
|随机结果，规律中途反转|50.00%|57.03%|73.44%|46.09%|

这是**机制对照**，不是此前四种奖惩条件的训练实验，也不是与已充分训练的 RL 比较。V200 在这里运行的是原权重在新任务中的行为，不是重跑或改写其旧测试结果。

### 能确认的进步

- 完整版相对 V200 在延迟选择和联合选择上的末窗优势，8 条配对种子序列都为正。去掉后继关联后，表现明显降低。这支持“真实后继关系的利用补上了一个有效机制”，而不是单纯增加参数。
- 完整版的联合选择从首 4 周期 55.47% 提升到末 4 周期 92.19%。新经验改变的是运行记忆与调用策略，不是参数。
- 合成核对中，相同条件下反复出现相反结果时，估计后果方差约 0.24644；稳定结果约 0.00701。噪声情况下证据不足代理约 0.07334，说明两种量在代码中确实分开了。它们仍不是校准过的概率保证。

### 暴露的不利结果：采纳门尚未做好

当前门要求 `实际均值差 - 2 * 样本标准误 > 0` 才替换策略。它在这组实验中降低了效率与末窗表现：完整版本在三类任务上都低于去门版本。

- 三步联合选择的 128 次候选判断中，实际试验均值为正但未采用 **58 次**。
- 随机反转任务中，这类情况为 **43 次**；关系反转后的最初两周期，完整版和去门版本的成功率均降到 **23.44%**，说明旧经验与新规律冲突尚未迅速解决。
- 这些“正均值被拒绝”不是 58/43 个已经证明正确的方案，仍可能含随机波动。但结合等预算去门对照，它们给出了明确的改进方向：不能把“需要实践验证”实现成“只要证据未达到这个全局阈值就一直保留旧策略”。
- 去门对照也执行、支付同样数量的真实试验，只是不根据结果决定替换，因此不能解读为“省掉试验后更快”或“实践验证无用”。当前结果否定的是把这一个采纳规则当成已经有效的整体设计，不否定真实试验的必要性。

下一关键件是更好地利用有限试验结果、区分局部改进与整体替换，并处理旧经验失效；不是回到游戏加规则、盲目降低门槛或继续堆相似任务。

## 仍未解决的边界

- 输入仍是有稳定含义的数值状态/动作描述，不是任意图像、语言或无结构数据。范围归一化不等于学会语义或忽略无关维度。
- 测试是小型、完整可观测、最多 5 步的回合；传播深度固定为本轮预算 6。不能据此声称复杂长程任务已经解决。
- 沿真实后继做规划是条件性预测，不是隐藏混杂下的因果识别；没有加入“原因占比”假定。
- 采纳门使用固定有限样本规则，不是正式 95% 区间或多次选择错误率保证。
- 这次同时改变了结构与手工编程权重，不能把全部改善单独归给“权重编辑”。记忆管理、归一化、矩运算及有限次展开属于公开算子结构；权重实现匹配、值通道、目标读出和采纳判别。不是声称整个算法只存在于 595 个参数中。
- 尚无同架构、同预算的正常梯度训练基线；尚无长期参数巩固、SLEEP 或陌生语义任务迁移。

## 使用与文件

- `model.py`：任务无关的网络、解析赋值函数、实际试验判断。
- `evidence/initial_written.pt`：新候选初始化检查点，不含运行记忆。
- `DERIVATION.md`：实验前写定的公式、假设及对照。
- `contract.json`：实验前预算与范围。
- `tasks.py`：独立的抽象任务；不被网络导入。
- `evidence/result.json`、`evidence/stored_review.json`：全部结果和重算记录。
- `evidence/202001.jsonl.gz` 至 `202008.jsonl.gz`：全部实际轨迹、候选/现行策略配对试验、采纳与未采纳记录。

最小调用顺序是：加载 `load_model` → 冻结参数 → `observe_transition` 记录真实结果 → `prepare` 冻结候选 → `forward` 选择行动 → 外部执行新的实际试验 → `assess_trials` 判断。不要把 `prepare` 的预测当成 `observe_transition` 的真实结果，也不要把新生成的预测传给实际试验门。

本次没有把候选部署进此前游戏模型，没有创建或恢复自动任务。V200/V201 及其他旧证据原样保留。
